# Project governance

This page maps binding project rules to their canonical owners and the mechanisms that reject violations. The linked owners remain authoritative; this map does not restate their full contracts.

## Decision status

| Status        | Authority and required evidence                                                                                                                                                           |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Proposed`    | Open and not current authority. Resolve it before dependent implementation.                                                                                                               |
| `Accepted`    | A current decision. Acceptance means the choice governs, not that its implementation exists.                                                                                              |
| `Implemented` | A current decision followed by links to the repository artifacts that enact that decision. Implementation is scoped to the record and never claims that the whole product is implemented. |
| `Superseded`  | History-only, with a link to the successor.                                                                                                                                               |
| `Deprecated`  | History-only because its context disappeared, with the reason and no invented successor.                                                                                                  |
| `Rejected`    | History-only, retained to prevent re-arguing the rejected option.                                                                                                                         |

The first nonblank line below `## Status` is the status value alone and exactly matches one of the six values above. Evidence and relationship prose follows in a separate paragraph.

Only `Accepted` and `Implemented` records are current authority. Round references to `Proposed`, `Superseded`, `Deprecated`, or `Rejected` records may describe history but may not supply a current rule.

## Changing a binding rule

Follow the existing owner first. Add or supersede an ADR only when the change meets the significance test in [AGENTS.md](../../AGENTS.md#decisions). Update the owner, its rejecting mechanism, and this map in one change. Where enforcement is review-only, label it honestly rather than inventing an automated gate.
