# Prior art

Projects inspected while designing `claude-session`, what was looked at in each, and what was taken or deliberately not taken. Everything here is **inspiration only** — no code is copied from any of these.

Entries record what was actually inspected. A project listed because it is popular, without a specific pattern attached, does not belong here.

Facts are distinguished from inference. An entry marked _(inferred)_ is a reading of observed behaviour or documentation, not a documented guarantee.

Last surveyed: 2026-07-28. Perishable entries are tracked in [research tracking](./research-tracking.yaml).

## The problem this project shares with others

Claude Code stores credentials and configuration in a single directory, so every instance a user runs shares one identity and one state. A cluster of open-source tools exists to work around this, and they converge on the same mechanism: point the child at a different configuration directory through its `CLAUDE_CONFIG_DIR` environment variable, giving each account or terminal its own independent tree.

That convergence is the strongest available evidence that environment injection is the right seam, and it is the mechanism this project uses. Where `claude-session` differs is in what it does around that seam.

## Account and session switchers

| Project                                                                                   | Inspected                                               | Pattern                                                                                                                                                                                                        | Taken / rejected                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [claude-account-switcher](https://github.com/ukogan/claude-account-switcher)              | Shell wrapper function, profile layout                  | A wrapper function reads a profile name as the first argument, sets the configuration directory, then launches the real binary. Shared configuration is **symlinked** from a main directory into each profile. | **Environment injection: taken.** **Symlinked shared config: rejected** — symlinks into a shared tree make "which file am I actually editing" ambiguous, break under bind mounts, and let one profile's write reach another. This project copies a credential seed instead.                                                                                                                                                                                                                                       |
| [claude-switch](https://github.com/hoangvu12/claude-switch)                               | Shim design                                             | An installed shim, ahead of the real binary on `PATH`, reads a pointer file on each invocation, sets the configuration directory, and `exec`s the real binary.                                                 | **Explicit resolution and a recursion guard: taken** — a shim named like its child is exactly the self-invocation hazard [process runtime](./process-runtime.md) guards against. **`exec`: rejected**, because this project needs post-flight work; see [ADR-0004](../decisions/0004-spawn-and-wait-child-supervision.md). **A global pointer file: rejected** — it makes the active account a machine-wide mode, so a second terminal silently changes the first. Session identity here is derived per terminal. |
| [claude-swap](https://github.com/realiti4/claude-swap)                                    | Switching model, parallel sessions, rate-limit rotation | Switches accounts without re-login, runs accounts in parallel, and can rotate automatically ahead of a rate limit, with a usage dashboard.                                                                     | **Parallel independent sessions: taken** — confirms per-terminal isolation is the useful unit, not a global mode. **Automatic rotation and usage dashboards: rejected for now** — real features, but they require modelling quota state the wrapper cannot observe reliably, and they are orthogonal to isolation. Explicit selection first.                                                                                                                                                                      |
| [claude-account-switcher (tray)](https://github.com/brenoluizdev/claude-account-switcher) | Scope                                                   | A Windows tray utility that opens a terminal with an account pre-selected.                                                                                                                                     | **Not applicable.** Confirms the demand is cross-platform, while this project is Unix-only; see [process runtime](./process-runtime.md).                                                                                                                                                                                                                                                                                                                                                                          |

The upstream request for native multi-account support is [anthropics/claude-code#44687](https://github.com/anthropics/claude-code/issues/44687). If it ships, the isolation layer here becomes redundant and the composition and supervision layers do not — worth re-checking rather than assuming.

## Wrapper and shim design

| Project                                         | Inspected                            | Pattern                                                                                                       | Taken / rejected                                                                                                                                                                                                          |
| ----------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`rustup`](https://github.com/rust-lang/rustup) | Proxy binaries                       | One binary installed under many names proxies to a toolchain-specific executable, resolving by argument zero. | **Explicit resolution before spawning: taken.** The multi-name proxy shape is not needed here — one wrapper, one child.                                                                                                   |
| [`direnv`](https://github.com/direnv/direnv)    | Environment injection boundary       | Modifies a child's environment and nothing else; implements no behaviour of its own.                          | **The narrow boundary: taken.** It is the model for the proxy seam in [the wrapper model](../explanation/wrapper-model.md) — a seam, not a feature.                                                                       |
| [`mise`](https://github.com/jdx/mise)           | Shim and resolution ladder           | Resolves a tool through a documented precedence chain rather than a bare path search.                         | **The ladder: taken**, including the rule that a candidate which exists but fails validation is an error rather than a reason to try the next rung.                                                                       |
| Cargo external subcommands                      | Dispatch to `cargo-<name>` on `PATH` | Unknown subcommands dispatch to an external binary.                                                           | **The general shape confirmed.** Note that this handles an unknown _positional_, not an unknown leading _flag_ — which is precisely the limitation that forces the argv pre-split in [the CLI surface](./cli-surface.md). |

## Rust CLI structure

## Configuration layering

| Project                                                                   | Inspected                        | Pattern                                                                                                | Taken / rejected                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`kustomize`](https://github.com/kubernetes-sigs/kustomize)               | Base-and-overlay composition     | Composes a final document from a base plus ordered overlays, declared in a manifest.                   | **The model: taken** — it is the shape of the pieces-plus-manifest design in [configuration](./configuration.md). **Its patch language: rejected** as far more machinery than composing a settings file needs.                                                                                                              |
| [RFC 7396, JSON Merge Patch](https://www.rfc-editor.org/rfc/rfc7396.html) | Merge semantics                  | A standard recursive object merge, with explicit nulls deleting keys.                                  | **Recursive object merge: taken.** **Null-deletes: rejected** — a settings piece legitimately sets a null value, so overloading it as a delete makes that unexpressible. **Array handling: rejected** — the RFC always replaces arrays, and additive lists genuinely need concatenation, so array strategy is per-key here. |
| [`figment`](https://github.com/SergioBenitez/Figment)                     | Provider layering and provenance | Layered providers with merge-versus-join semantics, and the ability to report where a value came from. | **Taken**, including per-key provenance reporting.                                                                                                                                                                                                                                                                          |

## Process supervision

| Source                                                                                                                                                   | Inspected                         | Pattern                                                                                                                                             | Taken / rejected                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Beyond Ctrl-C: the dark corners of Unix signal handling](https://sunshowers.io/posts/beyond-ctrl-c-signals/)                                            | Signal forwarding for supervisors | A boundary process managing process groups is responsible for forwarding signals; the ones the terminal sends to a group are the interesting cases. | **Taken**, with the correction that governs [process runtime](./process-runtime.md): in a **shared** foreground group the terminal already delivers to the child, so forwarding those signals double-delivers. The wrapper's job is to forward what the terminal does not broadcast. |
| [Signal handling — Command Line Applications in Rust](https://rust-cli.github.io/book/in-depth/signals.html)                                             | Handler safety                    | Handler-safe registration with the real work done outside the handler.                                                                              | **Taken.**                                                                                                                                                                                                                                                                           |
| [`signal-hook`](https://docs.rs/signal-hook/)                                                                                                            | API                               | The widely-used crate for this, with async-signal-safe primitives.                                                                                  | **Taken**; see [dependencies](./dependencies.md).                                                                                                                                                                                                                                    |
| [`sysexits(3)`](https://man.freebsd.org/cgi/man.cgi?query=sysexits&sektion=3) and [shell exit conventions](https://tldp.org/LDP/abs/html/exitcodes.html) | Exit-code vocabulary              | `sysexits` for a program's own failure classes; `126`, `127`, and `128 + N` as shell conventions.                                                   | **Both taken**, with the boundary rule in [exit codes](./exit-codes.md): `sysexits` before the child runs, the child's own status afterwards.                                                                                                                                        |

## Sandboxing

| Project                                                  | Inspected           | Pattern                                                                 | Taken / rejected                                                                                                                                                                                                                                                                  |
| -------------------------------------------------------- | ------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`bubblewrap`](https://github.com/containers/bubblewrap) | Namespace isolation | Unprivileged namespace isolation, including a synthetic home directory. | **Deferred, not rejected.** A genuinely stronger isolation boundary than an environment variable, and a plausible future hardened mode. Out of scope now: it changes the child's whole view of the filesystem, which is a much larger contract than this project currently makes. |

## Native child behaviour

Facts about `claude` itself that this design depends on. All are **externally owned and perishable**; see [research tracking](./research-tracking.yaml).

| Fact                                                                     | Status                                                                                                                   |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `CLAUDE_CONFIG_DIR` redirects the configuration directory                | Observed and relied upon by every tool in the switcher table. Not part of a documented stability guarantee _(inferred)_. |
| Credentials are stored in a file inside that directory on Linux          | Observed. Platform-dependent — other platforms use a system keychain _(inferred)_.                                       |
| Project-trust and onboarding state live in a separate file from settings | Observed _(inferred)_.                                                                                                   |
| `ANTHROPIC_BASE_URL` redirects the API endpoint                          | Documented behaviour, and the basis of the proxy seam.                                                                   |
| Baseline version for design purposes                                     | 2.1.183                                                                                                                  |

The wrapper consumes all of these **defensively**: a missing file is reported rather than fatal, an unparsable version is reported rather than fatal, and `doctor` surfaces each so a change upstream presents as a diagnosis rather than a crash.
